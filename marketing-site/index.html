THE POINT / 01

LemonPi doesn't reimplement Pi.

It intentionally uses Pi's subprocess RPC boundary instead of reimplementing Pi.

This preserves your existing authentication, models, settings, skills, extensions, and session files. Nothing about how Pi works underneath changes — LemonPi just gives the real process a native home.

Same Pi. Same auth. Same sessions.
Just a native window around the process.

INSIDE THE APP / 02

What the workspace actually gives you.

01

Command center

Every active subagent gets a live panel: role, task, model, effort, elapsed time, token usage, and current tool — plus the output it's producing, direct steering, and a stop control.

Watch the main agent think

Main Pi narrates its current actions, auto-expands the tools it's running, and streams provider-surfaced reasoning token by token as it arrives.

Main Pi never edits directly. Broad implementation work runs as bounded, sequential worker chunks, with an inspection checkpoint after each one.

03

Pick up where you left off

LemonPi lists the saved Pi sessions for your active project and reopens them through Pi's own switch_session — nothing is copied or migrated.

  • Audit the auth flow 2h ago
  • Draft the changelog yesterday
  • Fix updater signing 3d ago

Recent projects, their trust choices, and your last active workspace are remembered across launches.

04

Settings and packages, natively

Pi's user and project settings get a categorized native GUI, with a raw JSON escape hatch for anything new or extension-defined.

User and project packages install, update, list, and remove through Pi's own package manager. npm:pi-subagents and npm:pi-web-access, plus structured agent questions, are required core packages and installed automatically when missing.

THE BORING TECH BIT / 03

How the pieces actually talk.

No terminal scraping. No reimplementation. Just a supervised process boundary, end to end.

  1. React UI
  2. ↕ Tauri commands/events
  3. Rust process supervisor
  4. ↕ strict LF-delimited JSONL over stdin/stdout
  5. pi --mode rpc

LemonPi verifies its required subagent, web-access, and structured-question packages before launching Pi. Lifecycle data powers live observability, research agents get search tools, and clarifying questions become native LemonPi controls — terminal rendering is never scraped.

TRUST / 04

You choose how much Pi gets to touch.

LemonPi never silently approves project-local Pi resources. Opening a project always means choosing one of two paths first.

Trust and open

Launches Pi with --approve, using the project's own Pi settings, extensions, skills, and packages.

Flag --approve

Open safely

Launches Pi with --no-approve, ignoring project-local Pi settings, extensions, skills, and packages.

Flag --no-approve

Read this part

Pi and its extensions still execute with the user's operating-system permissions. LemonPi is a UI and process boundary, not a sandbox.
