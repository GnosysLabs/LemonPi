# LemonPi narration

First-party Pi extension bundled with LemonPi. It adds visible narration and supervisor/worker orchestration contracts to every Pi turn, defaults top-level `pi-subagents` delegations to background execution, and requests one guarded repair response if a run settles after tool activity without a closing explanation.

The async policy uses the public mutable `tool_call` extension hook and the package's existing `async` option. It does not patch or fork `pi-subagents`, and it does not rewrite timeout or budget arguments. Main Pi is kept interruptible: LemonPi blocks `subagent_wait`, requires Main Pi to end its turn after dispatching and narrating active work, and relies on the package's background completion notification to wake integration. The worker remains alive between Main Pi turns, so a new user message can receive an immediate supervisor response and be turned into direct worker steering.

Dispatch is risk- and scope-based rather than file-count-based, but Main Pi is always a read-only orchestrator. Bounded low-risk work—including cohesive UI changes that touch markup, styles, and state—uses a single-worker fast path. Broader work is divided into ordered, independently reviewable vertical chunks. Every worker handoff must name the chunk outcome, in-scope work, observable completion condition, and explicit out-of-scope remainder. LemonPi intentionally does not hard-code a provider or model: `pi-subagents` resolves the `worker` coding role through each user's settings.

The extension mechanically blocks Main Pi's file-editing tools and common shell-based project mutations while leaving inspection, search, tests, builds, status checks, and git-management operations available. It also rejects implementation tasks routed to writer-style specialist roles: specialists may investigate or advise, but project changes go to `worker`. Corrections should steer or resume the same worker whenever possible.

Reviewers and other specialists are optional tools, not pipeline stages. An independent reviewer requires an explicit user request, a material risk boundary, or a concrete `Review justification: ...`; LemonPi mechanically blocks ceremonial review calls and blocks a second reviewer pass unless the user explicitly requested multiple reviews. Delegations without explicit runtime verification disable `pi-subagents`' automatically inferred structured acceptance report because Main Pi owns integration and validation. Only blocker-level findings justify a repair pass, and Main Pi validates that repair directly instead of creating a review-repair-review loop.

Acceptance configuration is preflighted before a worker launches. LemonPi defaults unspecified acceptance to `none` so `pi-subagents` cannot infer a post-run gate that Main Pi did not configure. Explicit `verified` acceptance is allowed only with at least one well-formed runtime `verify` command; merely asking the worker to run tests or report validation does not satisfy the package API. A malformed verified contract is blocked immediately without consuming a worker run.

The runtime permits sequential chunks but prevents overlapping writers: only one writer may own the shared checkout at a time, even if the user sends another message while it is working. After a completed chunk Main Pi inspects the diff, checks its stated acceptance condition, reports the checkpoint, and then dispatches the next bounded chunk with updated context. Two consecutive failed chunks stop automatic retries so repeated failure becomes an explicit blocker instead of an invisible loop. Parallel writers require explicit isolated worktrees.

If a delegated tool call fails and no corrected delegation follows, LemonPi queues one hidden recovery turn requiring Main Pi to diagnose the cause, preserve partial work, and re-delegate the remaining slice when retrying can help.

The extension also handles LemonPi's private RPC control messages for direct child steering and stopping. It validates the target and calls `pi-subagents`' public `subagents:rpc:v1` `steer` or `stop` method, so Command Center intervention reaches the selected background run without an LLM relay or transcript pollution.

LemonPi loads `extensions/narration.ts` explicitly for every managed Pi process. It is not installed into the user's global Pi configuration.
